# Hungry Wolf · agent rules

Shared instructions for every coding agent (Claude, Codex) working in this repo. `CLAUDE.md` includes this file.

## Production and branches

- `tune/v2-clarity-economy-audio` is production. The Pages workflow (`.github/workflows/pages.yml`) publishes on every push to it; live players and a live daily leaderboard depend on it.
- Never push, merge, or trigger the deploy workflow (including `workflow_dispatch`). The owner does that.
- Work on a feature branch created from `origin/tune/v2-clarity-economy-audio` (the local `tune/...` ref can be stale; fetch first). Do not merge to `main`.
- Commit only when the owner asks. Preserve unrelated working-tree changes and untracked files; never reset, checkout or revert files you did not touch.

## Sources and releases

- Runtime sources live at the repo root: `index.html`, `rescue.css`, `rescue.js`, `rescue-engine.js`, `rescue-daily.js`, `rescue-services.js`, `rescue-share.js`, `rescue-audio.js`, `rescue-voices.js`.
- `play/<version>/` is packaged, immutable release output. Never hand-edit it; `classic.html` and every `play/*/index.html` are generated by the packager.
- A shipped change is a new release. Bump the version in all of: `index.html` (asset paths and the `load-version` span), `rescue-services.js` (`VERSION`), `scripts/package-rescue.cjs`, `tests/rescue-release.test.cjs`, the README release paragraph, and a new `ROLLBACK_PLAN.md` section. Then run the packager and commit the generated `play/<version>/` with the source change.

## Do not touch without asking

- `rescue-engine.js`, `rescue-daily.js` (shared verbatim with the backend as `apps-script/DailyRules.gs`) and everything under `apps-script/`. The daily puzzle is defined by seeded random streams and the order they are consumed.
- The score-submission contract in `rescue-services.js`: `MODE`, `RULESET`, `FORM_FIELDS`, `payload()`, and player-name encoding. The Google Form, Sheet formula and published CSV are the backend.
- Game rules, scoring, copy tone, audio and visual design, unless the task says so.

If a task seems to need one of these, stop and ask.

## Style

- No new dependencies, no `package.json`, no bundler, no framework. Node built-ins only in scripts and tests.
- No reformatting or restyling of existing code. Match the existing dense, dependency-free style. Smallest diff that works.
- Tests use `node:test` and run source files in `node:vm` with hand-built DOM stubs (see `tests/rescue-flow.test.cjs` and `tests/rescue-share.test.cjs`). Add coverage there where the harness allows.

## Build, test, verify

Serve locally with `python3 -m http.server 8000`. The root page loads packaged assets, so run the packager after editing runtime sources. Before calling anything done, run all of these and show the output:

```sh
node scripts/package-rescue.cjs
node --test tests/*.test.cjs
node tests/rescue-balance.cjs
node scripts/audit-animal-distribution.cjs
git diff --check
```

`node scripts/build-site.cjs <empty-dir>` builds the exact Pages artifact; use it to confirm what will be published.
